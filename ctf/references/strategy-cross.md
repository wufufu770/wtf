# 通用认知纪律（cross · STG-X*）

> 跨库策略宿主：认知纪律主产地（设计 §3.1）。X 系列 = 不绑定单一题型库的「这类题怎么想」纪律；

## 简单档

### STG-X02 旗位置先验——先问「旗在哪」再穷举「旗是什么」
- **类型**：认知纪律
- **规则**：明文穷举/取旗逻辑推演无果时，旗未必在明文里——旗可能就是密钥本身、藏在状态载体（cookie/session）或非常规执行层；先枚举存放位置，再决定攻击对象。
- **触发场景**：①有加解密 oracle 且题目要求「密钥」类输出（替换密码映射表）；②业务逻辑推演显示取旗逻辑上不可能（rarity=0 类）；③客户端校验存在但常规 JS/源码审计找不到校验逻辑；④题目所问比常规明文「少一层转换」。
- **行动序列**：1) 盘点全部「非明文载体」：密钥表、cookie、session、缓存、渲染层、资源段；2) 逐个问「旗能不能就在这」；3) oracle 可用时喂已知明文收集映射对、重建完整表（服务端短输入拒绝时重复填充绕过）；4) 载体可离线取时先解包再判断（base64/zlib 逐层剥）。
- **反例与边界**：旗确在明文的常规题不受益（本策略是「穷举无果后」的转向纪律，非首选路径）；载体强加密且无 oracle 时位置枚举也无法推进 → 转密码分析。
- **适用档**：简单、超级难（主触发：简单——认知陷阱型简单题高发带；超难档以「位置反直觉」变体出现）
- **技能范围**：密码学（主）、Web安全、编码分析；cross
- **状态**：verifying（落库即推进：独立来源群 3 ≥ 2 判据满足——csaw / plaidctf×2 三独立事件印证、无稳定反例；设计草稿注「满足 verifying 判据，待登记印证推进」，2026-10-23 登记即生效）
- **证据链**：P1-S06（CSAW 2015 notesy｜p4——旗在密钥表不在明文，队内卡壳近 20 小时）｜泛化证据（低优先级并入）：P1-H10（PlaidCTF 2017 pykemon——游戏逻辑不可能，旗路径在 Flask cookie）、P1-H12（PlaidCTF 2021 watness3——答案校验藏 WebGL shader）｜独立来源群 3（csaw / plaidctf×2，跨 6 年，三形态）。
- **关联**：知识锚 → [[替换密码·旗即密钥（密钥表重建）]]、[[游戏状态存 Flask cookie（rarity=0 取旗不可能 → 离线解码）]]、[[答案校验藏于 WebGL shader（路径编码阶段状态机）]]。
- **应用记录**（verifying 态待实战实证，append-only）：暂无（verifying→verified 需 ≥1 条 PASS）

## 困难档

### STG-X05 魔改原语先定家族再自实现——指纹定位→裸写对拍→对称求逆
- **类型**：方法论
- **规则**：二进制内自定义/魔改密码原语不指望现成库直接解：先常量指纹（S 盒/轮数/表长/魔数）定位算法家族，再裸写正向实现与目标对拍，最后对称写逆（或截获轮密钥）。
- **触发场景**：①加密逻辑无标准库符号但含可疑常量表；②标准工具按假定算法解不通；③输出块长/轮数与标准参数对不上。
- **行动序列**：1) 常量指纹扫描（表值/表长/轮常量对照已知算法族）；2) 裸写正向实现与目标对拍（已知明密文对）；3) 对拍一致后对称求逆，或从 key schedule/轮密钥侧截获恢复；4) 全换表场景直接照抄目标表实现。
- **反例与边界**：指纹全灭（真·新原语）→ 转 STG-K01 代数减法检；魔改在结构而非常量（截轮/换序）时对拍须覆盖多轮次输入；动静态不可分（VM 字节码承载原语）时轨迹留痕优先——见 [[brainfuck VM 执行轨迹跟踪（解码即抹零）]]。
- **适用档**：困难（主触发：困难——魔改原语主力带）
- **技能范围**：密码学（主）、逆向分析、移动安全（cross）
- **状态**：verifying（落库即推进：独立来源群 3 ≥ 2 判据满足——四事件三形态印证、无稳定反例）
- **证据链**：P2-D06（mtp 2018｜六星——表全换魔改 AES 靠常量指纹定位 + 裸写对拍）｜P2-D13（Insomni'hack Teaser 2017｜pwning——AVX2 无密钥轮函数对称逆推）｜P2-D87（MeePwn 2018 Quals｜p4——魔改 AES 截轮，从 key schedule 逆向恢复轮密钥）｜P2-D97（阿里聚安全 2016｜六星——SM4/DES/SHA 大礼包常量指纹 + F5 恢复）｜独立来源群 3（六星 / pwning / p4 三个独立 author-群 × 四事件）。
- **关联**：知识锚 → [[魔改 AES 常量指纹识别（表全换场景裸写实现）]]、[[AVX2 轮函数对称逆推（无密钥加密器）]]、[[多进程互斥校验逆向 + AES 轮密钥恢复（3-process lock）]]、[[密码算法大礼包识别（常量指纹 + F5 恢复 + SM4 收官）]]、[[brainfuck VM 执行轨迹跟踪（解码即抹零）]]；姊妹策略：STG-K01（高级外观先做减法——K01 管「能否不硬碰」，X05 管「确实要硬碰时怎么打」）。
- **应用记录**：（verifying 态待实战实证，append-only）：暂无

### STG-X06 非标准格式先逆生成器——定义在材料里，不在猜里
- **类型**：决策规则
- **规则**：自定义字母表/自造格式题，标准解码器全家桶阴性后停止盲试：假设「格式定义就在题给材料里」——逆向写入器/生成器逻辑或定位其内嵌表，按定义重建解码。
- **触发场景**：①字符域异常（非 64/16 标准基、自定义符号集、排版属性二值化）；②挑战产物带同构增量写入痕迹；③编码例程可定位（生成脚本/混淆代码内表/固件写码例程/内存映像表区）。
- **行动序列**：1) 提取全部可执行/脚本材料找写入或编码例程；2) 静态还原映射表或增量规则；3) 按逆向出的定义实现提取器；4) 内存映像可得时直接 dump 表区比对。
- **反例与边界**：标准格式仅嵌套多层时走 [[排版 Bacon 密码（斜体/正体交替 5bit）]] 同族的解链识别，不算自定义格式；定义真不在材料里（社区知识型 glyph 文）→ 转知识库/外部语料检索；与 SKILL.md §3「限制条件的利用」的边界——该纪律管「线索都有用」，本条管「定义可从生成侧恢复」的具体路径。
- **适用档**：困难（主触发：困难）
- **技能范围**：编码分析（主）、取证分析、逆向分析（cross）
- **状态**：verifying（落库即推进：独立来源群 3 ≥ 2 判据满足——三事件两形态印证、无稳定反例）
- **证据链**：P2-D46（picoCTF 2019｜Dvd848——PNG IEND 尾随增量字节，逆向写入器定位块边界）｜P2-D57（picoCTF 2019｜Dvd848——BMP 位平面隐写跟随写入器逻辑参数化提取）｜P2-D88（gslab 2017｜六星——自定义 base64 表从内存 dump 定位）｜P2-D67（XDCTF 2015｜六星——pyobfuscate 还原后露出自定义移位表）｜独立来源群 3（Dvd848 / 六星 × 2 事件，三事件）。
- **关联**：知识锚 → [[PNG IEND 尾随增量字节提取（逆写入器）]]、[[BMP 位平面隐写读取（跟随写入器逻辑）]]、[[自定义字母表 base64（内存 dump 定位表）]]、[[pyobfuscate 混淆还原（lambda 派发 + 自定义表 base64）]]、[[排版 Bacon 密码（斜体/正体交替 5bit）]]；姊妹策略：STG-X05（先定家族再自实现——X06 管格式定义、X05 管原语实现，同「从生成侧拿规格」族）。
- **应用记录**：（verifying 态待实战实证，append-only）：暂无

### STG-X07 载体自称数据≠载入器当数据——eval 家族载入面即执行面
- **类型**：决策规则
- **规则**：服务端/客户端载入用户可控文件时，载体扩展名与语义自称不构成安全边界：载入器属 eval 家族（反序列化器/动态加载器）即执行面——先审载入器，再信载体。
- **触发场景**：①用户可控文件被载入且载入器为反序列化/动态加载形态；②题面强调「模型/图片/文档」等数据外观；③上传校验只查扩展名/MIME。
- **行动序列**：1) 定位载入器符号/接口形态；2) 构造 __reduce__/gadget/魔术方法载荷触发执行原语；3) 执行受限时找「异常路径仍读结果」类旁路；4) 版本窗口核对（载入器安全默认值随版本翻转）。
- **反例与边界**：载入器为安全解析器（受限反序列化/白名单模式）时执行面关闭 → 转数据层攻击（参数注入/模型后门）；版本敏感度极高——torch 载入安全默认值 2.6 起翻转（Q5 版本窗口纪律首案），撞例必须标注版本区间；载体无任何代码执行语义时勿强套（纯数据解析题）。
- **适用档**：困难（主触发：困难）
- **技能范围**：AI安全（主）、Web安全（cross；移动侧模型/固件载入同构）
- **状态**：verifying（落库即推进：独立来源群 4 ≥ 2 判据满足——四事件四载体形态印证、无稳定反例）
- **证据链**：P2-D34（Hackergame 2022｜USTC——torch.load pickle 载体模型文件，「模型文件=数据」是本题认知陷阱）｜P2-D20（Midnight Sun 2019 Quals｜perfect blue——phar 图片 stub 伪装 + 魔术方法命令拼接）｜P2-D37（Trend Micro Quals 2018｜p4——XMLDecoder 直接执行 + SpEL 注入）｜P2-D85（Ekoparty 2016｜pwning——ysoserial 载荷类名长度前缀改写落目标类）｜独立来源群 4（hackergame-2022 / midnightsun-2019 / trendmicro-2018 / ekoparty-2016，四载体：pickle / phar / XMLDecoder / ObjectInputStream）。
- **关联**：知识锚 → [[torch.load 反序列化 RCE（pickle 载体模型文件）]]、[[phar 反序列化（图片 stub 伪装 + 魔术方法命令拼接）]]、[[Java 反序列化 XML gadget + SpEL 表达式注入（T() 静态调用）]]、[[Java 反序列化 RCE（ysoserial 载荷类名改写）]]；姊妹策略：STG-X04（题面类别≠技术类别——X04 管路由、X07 管安全边界，同「以技术实质对待载体」族）。
- **应用记录**：（verifying 态待实战实证，append-only）：暂无

## 超级难档

### STG-X01 勿信补丁——修复覆盖面以 diff 验证
- **类型**：认知纪律
- **规则**：修复公告/commit message ≠ 漏洞消除——以二进制 diff 验证每个危险触点后，才允许宣布「已修好」。
- **触发场景**：①目标存在「已修复」公告/新闻，利用手法仍在窗口内；②1-day/NDAY 打靶，线上新旧版本并存；③泄露源码或旧样本可与新版本对照取材。
- **行动序列**：1) 取 fix 前后两版二进制；2) 定位补丁函数（bindiff/符号差）；3) xref 列出**全部同类危险调用点**（不止公告引用那处）；4) 逐点验证未覆盖处可否仍触发；5) 命中未修点 → 利用链重放。
- **反例与边界**：全部触点真修完 → 本策略不产出利用，转新漏洞挖掘；上游框架级整体升级时触点法不适用，改查版本兼容层。
- **适用档**：困难、超级难（主触发：超级难——真实软件 1-day 场景；实战漏洞复现全档适用）
- **技能范围**：二进制漏洞挖掘（主）、逆向分析；cross（Web 1-day 组件场景可平移）
- **状态**：verifying（P2 批次推进：独立来源群 2 ≥ 2 判据满足——RealWorldCTF / hackergame 两源印证、无稳定反例；2026-10-29 登记即生效）
- **证据链**：P1-H05（RealWorldCTF 2018 P90 Rush B｜perfect blue，赛内未解、赛后两天完成利用——第一版 fix 只修第一处 `Get()` 调用，被报告的第二处仍在；WP 结论段原话 "never trust a fix. Always verify it actually fixes the bug!"）｜独立来源群 2（RealWorldCTF-2018 + P2 扩充：hackergame-2024，2026-10-29——P2-D81 Docker sudo 白名单三路绕过，布尔选项带值覆盖证伪「不可覆盖」假设，运维版证据）。
- **P2 证据扩充**：P2-D81（Hackergame 2024｜USTC——「加了限制≠限制闭环」，与本题同一纪律的容器运维场景）。
- **关联**：知识锚 → [[「勿信补丁」修复覆盖面验证纪律]]；姊妹策略：STG-P02（泄露源码≠现役二进制——同属「不信二手描述、只信本地 diff」纪律族）、STG-W01（组件在场≠版本安全——同属「版本/修复状态不信表面」族）。
- **应用记录**：（hypothesis 免）

### STG-X03 外观强度≠攻击面位置——先审业务层再碰协议层
- **类型**：决策规则
- **规则**：协议外观的密码学强度不指示攻击面位置——SSL/TLS 外观的服务，门禁可能只是未播种 `rand()` 的回显匹配；先反编译 handler 业务逻辑，再决定攻哪层。
- **触发场景**：①服务外观「强」（TLS/加密协议包装）；②连接后行为简单（回显/单轮问答/门禁模式）；③密码学层无从下手（无握手缺陷、无密钥泄漏路径）。
- **行动序列**：1) 反编译 handler 主体（Ghidra/IDA）；2) 查熵源——`rand()` 前有无 `srand(time(NULL))`；3) 查门禁比较逻辑是否可预测/可回放；4) 业务层无门 → 才转协议/实现层攻击。
- **反例与边界**：真密码学挑战（题面明示攻协议）不走此路；纯黑盒无反编译条件时以行为指纹替代（回显值是否随时间可预测）。
- **适用档**：困难、超级难（主触发：超级难——非预期解高发带）
- **技能范围**：二进制漏洞挖掘（主）、密码学、Web安全；cross
- **状态**：hypothesis（种子）
- **证据链**：P1-H08（Dragon CTF 2020 babyshell｜p4｜38 solves——作者预期 shellcode 题被 SSL 门禁非预期解；Ghidra 反编译注释原话 "this value is NOT seeded!"）｜独立来源群 1。
- **关联**：知识锚 → [[rand() 未播种的服务端门禁（SSL 回显可预测）]]；姊妹策略：STG-K01（高级外观先做减法——同属「先拆外观再上重武器」纪律族）。
- **应用记录**：（hypothesis 免）

### STG-X04 题面类别≠技术类别——以附件技术实质路由
- **类型**：认知纪律
- **规则**：题面宣称/登记的类别 ≠ 附件技术实质——路由（解题工具链与采集落桶）前先验附件技术指纹，按实质分流。
- **触发场景**：①题面类别与附件形态不符（「AI/模型」外观给 Windows PE、取证登记实为恶意样本逆向）；②采集落桶时登记口径与技术实质冲突（P1 试运行 C-10：apt42 取证类登记按技术实质落 reverse 桶）；③解题工具链按题面类别选择后无从下手（先验「逆向模型」失败）。
- **行动序列**：1) 附件指纹先于题面阅读（file/strings/壳与段属性/模块 import）；2) 以实际操作对象归类（技术实质——PE 双模式逆向就是 reverse，无论题面写什么）；3) 路由到对应工具链/落桶；4) 登记侧记录「题面类别 vs 技术类别」双口径，撞例反哺映射表。
- **反例与边界**：题面与实质一致的常规题无增益；纯理论题（无附件）不适用；跨类复合题以**主攻面**归类，副面记入条目标签不另开桶。
- **适用档**：简单、困难、超级难（主触发：超级难——来源条目档位；路由错误全档高发，采集侧无档别差异）
