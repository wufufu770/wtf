## 超级难档

### STG-W01 组件在场≠版本安全——pin 版本 1-day 时间窗
- **类型**：决策规则
- **规则**：组件在场 ≠ 版本安全——前端库以构建时 pin 的**具体版本**为准，1-day 漏洞按「披露日 vs 构建/部署日」时间窗匹配，不以「用了知名组件」或「最近才部署」推断。
- **触发场景**：①目标页面引用知名前端组件（DOMPurify/sanitize 系列/框架全家桶）；②版本可考（构建产物内嵌 pin 值/依赖清单/资源路径指纹）；③赛事/目标窗口内该组件存在近期披露漏洞（1-day/NDAY）。
- **行动序列**：1) 提取实际加载版本（渲染后生效值优先于 CDN 路径默认）；2) 对照 CVE/issue 时间窗：披露日 ≤ 部署日 且 部署日 ≤ 修复引入日 → 窗口命中；3) 命中 → 按公开 PoC/变体路线复现，不重复挖 0-day；4) 窗口外（pin 版本已含修复）→ 转组件集成方式（自定义策略/绕过配置），不恋战。
- **反例与边界**：组件无版本可考（动态拉取 HEAD）→ 时间窗不可判，改攻集成方式；闭源自研组件无 CVE 覆盖，转代码审计；「最新版」也有未披露 1-day，窗口法只解决**已知漏洞的版本匹配**，不替代通用审计。
- **适用档**：超级难（主触发：超级难——需同时读 pin 值、对时间窗、复现 PoC 的复合动作）
- **技能范围**：Web安全
- **状态**：hypothesis（种子）
- **证据链**：P1-H11（TokyoWesterns 2020 bfnote｜p4——DOMPurify pin 在 2.0.7，赛期内 2020-08 披露的 mglyph mXSS 1-day 恰在窗口内；完整 mglyph 载荷在 WP，非预期解）｜独立来源群 1。
- **关联**：知识锚 → [[DOMPurify pin 版本 1-day 时间窗（mglyph mXSS）]]；姊妹策略：STG-X01（勿信补丁——同属「版本/修复状态不信表面」纪律族：X01 验证「已修复」、W01 验证「在场安全」，1-day 窗口是共同底座）。
