## 简单档

### STG-P03 自造防护≠标准语义——checksec 报告须验实现
- **类型**：决策规则
- **规则**：checksec 报「无 canary」≠ 程序无防护——自造 guard 若为二进制内固定常量，按原字节回填即绕过；工具报告只述标准语义，实现须亲手验证。
- **触发场景**：①checksec 报 No canary found 但溢出试跑崩在栈检查比较处；②二进制含非标准防护痕迹（浮点比较、自定义异或常量、非常规保存位置）；③崩溃点回看发现被覆盖槽位语义是「guard 回读」而非用户数据。
- **行动序列**：1) 定位 guard 实现（比较指令 xref：与谁比、存哪、何时回填）；2) 判常量性：跨次运行同值（固定常量）还是随机（真 canary）；3) 固定常量 → payload 对应区段按原字节回填；4) 配合 NX/PIE 状态选攻击面（NX disabled + 地址已知 → ret2stack shellcode）；5) 标准语义防护（glibc canary）才走常规绕法（泄露/格式化串）。
- **反例与边界**：标准实现的标准防护按常规语义对待，勿强套自造假设；商业加固壳的私有语义需单独建档积累；guard 参与多轮变换（非单次回填）时逐轮还原再回填。
- **适用档**：简单、困难（主触发：简单——自造防护多见于初级赛题的「教学陷阱」；P2 困难档样本已验证泛化）
- **技能范围**：二进制漏洞挖掘
- **状态**：verifying（P2 批次推进：独立来源群 2 ≥ 2 判据满足——CSAW / Insomni'hack 两源印证、无稳定反例；2026-10-29 登记即生效）
- **证据链**：P1-S08（CSAW 2015 precision｜p4——浮点存储的自造 stack guard 为固定常量，回填原字节绕过 + ret2stack shellcode 直达；「可复现强」样本，本机可复算）｜独立来源群 2（csaw-2015 + P2 扩充：insomnihack-2022，2026-10-29）。
- **P2 证据扩充**：P2-D101（Insomni'hack 2022｜p4——Android 物理镜像取证「UI 锁≠加密」：屏幕锁自造语义≠存储加密，工具报告须验实现的移动版判例）。
- **关联**：知识锚 → [[自定义浮点 stack guard 固定常量回填 + ret2stack shellcode]]；姊妹策略：STG-P01（活跃元数据零填充——同属「溢出前先审栈上数据语义」纪律族）。
- **应用记录**：（hypothesis 免）

## 困难档

### STG-P04 正门封死枚举信任边界对侧——沙箱/强防护的目标转移
- **类型**：决策规则
- **规则**：直接目标被沙箱/强防护/白名单封死时不与防护正面对抗：系统化枚举信任边界的对侧对象（父进程/宿主机/相邻数据/旗所在层），把攻击面转移到防护未覆盖一侧。
- **触发场景**：①子进程 seccomp 全拦截但旗/敏感数据在父进程或边界外；②PIE/Full RELRO 封死地址型利用但逻辑标志在栈上相邻数据；③运行环境白名单（sudoers/容器策略）限命令但宿主资源可达。
- **行动序列**：1) 画信任边界图（谁被限制、限制覆盖哪侧）；2) 枚举对侧可触达对象（未隔离进程/挂载点/相邻变量/设备文件）；3) 找边界穿越原语（procfs 命名空间/镜像走私/长度错配溢出）；4) 对侧读旗或提权后回取。
- **反例与边界**：边界完全闭合（真隔离）→ 转防护实现缺陷（版本/配置漏洞）；对侧触达但无读原语时先升权限再取数据；无明确边界的裸题不适用（STG-K01 减法检优先）。
- **适用档**：困难（主触发：困难）
- **技能范围**：二进制漏洞挖掘（主）、数据安全（容器/宿主边界场景）
- **状态**：verifying（落库即推进：独立来源群 3 ≥ 2 判据满足——三事件三形态印证、无稳定反例）
- **证据链**：P2-D31（Midnight Sun 2019 Quals｜perfect blue——seccomp 拦截 syscall、旗在父进程，越界写穿透打父进程）｜P2-D104（Technion DDD 2021｜Dvd848——PIE/Full RELRO 下攻击目标从地址退化为栈上相邻认证标志）｜P2-D81（Hackergame 2024｜USTC——Docker sudo 白名单三路绕过：宿主侧 procfs 穿越/设备走私/镜像 SUID）｜独立来源群 3（midnightsun-2019 / technion-2021 / hackergame-2024，三形态：进程边界 / 栈布局边界 / 容器边界）。
- **关联**：知识锚 → [[VM 寄存器索引截断越界（16-bit 无符号折返 + seccomp 打父进程）]]、[[相邻变量覆写改认证标志（authenticated 旁路）]]、[[受限 sudo Docker 白名单三路绕过（SUID 走私 / procfs 穿越 / 选项覆盖）]]；姊妹策略：STG-X03（外观强度≠攻击面位置——X03 管「先审哪层」，P04 管「正门封死后转移到哪」）。
- **应用记录**：（verifying 态待实战实证，append-only）：暂无

## 超级难档

### STG-P01 活跃元数据零填充与循环计数收敛
- **类型**：方法论
- **规则**：溢出覆盖「仍在使用」的栈上元数据时，0x41 习惯填充会先崩在劫持点之前——改零填充/还原原值；循环计数字段收敛到最小迭代数，让溢出点即退出点即劫持点。
- **触发场景**：①溢出区间覆盖运行期仍被读取的栈槽（结构体字段/文件长度/循环计数）；②0x41 填充后崩溃点在劫持点**之前**（回看崩溃现场被覆盖的元数据）；③循环以计数变量控制（如 zip 目录项数）且迭代体内有可溢出写。
- **行动序列**：1) 引用追踪：定位溢出后仍被读取的栈槽清单；2) payload 对应区段置 0 或还原原值；3) 循环计数调至最小迭代数（如置 2：第 2 次迭代触发溢出后即满足退出条件）；4) 前置检查（fileLen 上限等）用尾部零填充绕过；5) ret 前保留必要指针、ROP 接管。
- **反例与边界**：被覆盖区为「劫持后不再读」的惰性区时零填充无增益；元数据语义复杂（间接指针链）时逐槽回读崩溃点迭代收敛，不做一次性全零。
- **适用档**：困难、超级难（主触发：超级难）
- **技能范围**：二进制漏洞挖掘
- **状态**：hypothesis（种子）
- **证据链**：P1-H07（RealWorldCTF 2018 P90｜perfect blue——"a lot of metadata on the stack that is still being used" → 零填充；`nCentralDirectoryEntries_Total` 置 2 即溢出+退出循环）｜独立来源群 1。
- **关联**：知识锚 → [[栈溢出活跃元数据零填充与循环计数收敛]]；姊妹策略：STG-P03（自造防护≠标准语义——同属「溢出前先审栈上数据语义」纪律族）。
- **应用记录**：（hypothesis 免）

### STG-P02 泄露源码≠现役二进制——逆向为准，源码只作参考
- **类型**：决策规则
- **规则**：现役二进制的利用分析以逆向为准、泄露源码只作命名/结构参考；源码-二进制差异处（补丁痕迹、缺失函数）优先审计。
- **触发场景**：①题目同时给出源码与二进制/服务，且版本关系存疑（泄露年份早于赛题）；②按源码逻辑打不通（函数缺失、分支变化、常量更新）；③1-day/NDAY 打靶，公开补丁只落在二进制侧（源码树未同步）。
- **行动序列**：1) 二进制行为基线：关键函数指纹（存在性/参数/常量）与源码逐一对照列差异；2) 差异处优先审计——补丁痕迹意味着漏洞族在此活跃；3) 源码只用于命名/结构理解加速（IDA 结构体导入、符号恢复），逻辑判断一律以反编译为准；4) 无差异确认（编译一致性验证）后才可全文照读源码。
- **反例与边界**：纯源码题（无二进制）不适用；源码与二进制确认同版（同 hash/同编译产物验证）时源码可直接分析，省逆向时间；闭源黑盒服务转行为指纹路线。
- **适用档**：困难、超级难（主触发：超级难——真实软件 1-day 场景高发；P2 困难档样本已验证泛化）
- **技能范围**：二进制漏洞挖掘（主）、逆向分析（手段性副域，主路由仍 pwn）
- **状态**：verifying（P2 批次推进：独立来源群 3 ≥ 2 判据满足——RealWorldCTF / hackergame / mtp 三源印证、无稳定反例；2026-10-29 登记即生效）
- **证据链**：P1-H06（RealWorldCTF 2018 P90 Rush B｜perfect blue——2007 年 CS:GO 泄露源码与 2018 现役二进制分叉，补丁只落二进制；WP 原话 "We could have saved a lot of time by just opening the binary up in IDA"）｜独立来源群 3（RealWorldCTF-2018 + P2 扩充：hackergame-2022 / mtp-2018，2026-10-29）。
- **P2 证据扩充**：P2-D72（Hackergame 2022｜USTC——8051 固件与 .rst 源码同源分叉，对照加速定位而非盲信任一侧）、P2-D98（MTP 2018｜六星——OpenGL 顶点在 NativeActivity 资源段而非源码所指处，交叉引用为准）。
- **关联**：知识锚 → [[泄露旧源码 ≠ 现役二进制]]；姊妹策略：STG-X01（勿信补丁——同属「不信二手描述、只信本地 diff」纪律族：X01 管修复公告、P02 管泄露源码，同一 P90 一题两律）。
- **应用记录**：（hypothesis 免）
